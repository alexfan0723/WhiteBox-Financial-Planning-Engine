# Public-Safe Boundaries

This repository is intended to be safe for public collaboration.

## Do Not Publish

- customer data
- private financial plans
- production logs
- vendor-specific deployment details
- private prompts
- internal release evidence
- unreleased core calculation code
- credentials, tokens, or API keys

## Preferred Public Content

- external-facing architecture
- sanitized examples
- interface schemas
- test conventions
- research methodology
- market assumption notes
- contribution guidelines

## Language Rule

Use product and research language that an external collaborator can understand.

Avoid internal-only implementation labels, MVP deployment architecture, and temporary system names.
