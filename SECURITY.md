# Security Policy

## Reporting

Please do not open public issues for security vulnerabilities, customer data exposure, model leakage, or financial-output integrity problems.

Report sensitive issues privately to the project owner.

## Sensitive Data Rules

Do not submit:

- customer financial data
- identity documents
- account statements
- insurance policy files
- private advisor notes
- production logs
- model prompts containing private business logic
- deployment credentials or tokens

## Financial Integrity Issues

Financial-output integrity issues are treated as security-relevant when they can cause:

- incorrect household asset or liability treatment
- double counting
- missing liability recognition
- incorrect retirement or solvency risk output
- preview output being presented as formal output
- model-generated numbers being treated as verified calculations

When in doubt, report privately first.
